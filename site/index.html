The language a small model can write
and a compiler can prove.

Tez is a small, pure, strictly checked language. Programs are verified free of out-of-range indexing, division by zero, missing cases, runaway recursion and broken contracts, then compiled to WebAssembly. A 4B-parameter model can learn the whole language from one page.

Proved, not tested
Every index, division and recursion is checked by an SMT solver at compile time. If Tez cannot prove it, it does not compile. No warnings exist to ignore.

      
Made for small models
One way to do each thing, no shadowing, no operator overloading, no implicit anything. The whole language card is about 1,000 tokens.

      
Token-lean
Measured with the Gemma 4 tokenizer: the same programs take about 12% fewer tokens than their TypeScript twins (16% when the lines that exist only to be proved are not counted), and 36 of 38 keywords are a single token.

      
WebAssembly GC
Compiled output uses WasmGC and a tiny runtime. A recursive fib(30) runs in about 0.03 s compiled, against 0.65 s in the reference interpreter.

      
Entirely in the browser
Parser, type checker, formatter, compiler and the app runtime all run client-side. No server, no install, no account.

      
Errors an agent can fix
Sixty-one stable error codes with spans, expected forms, counterexamples and machine-applicable fixes, as JSON for tools and as plain text for people.

    


    

      
When the compiler says no, it says why.

      
Real output from tez check. The first program reads a list at an arbitrary index. Tez finds the input that breaks it.

      

        

          
fn at(xs: List[Int], i: Int) -> Int = xs.get(i)

          
error[E_INDEX_BOUNDS]: the index may be out of range
  --> a.tez:1:39
  |
1 | fn at(xs: List[Int], i: Int) -> Int = xs.get(i)
  |                                       ^^^^^^^^^
   = counterexample: i = 1, xs.len() = 1

        

        

          
fn at(xs: List[Int], i: Int) -> Int
  requires 0 <= i && i < xs.len()
  = xs.get(i)

fn main() -> Int = at([1, 2, 3], 5)

          
error[E_PRECONDITION]: this call may violate the
precondition of `at`
  --> b.tez:5:20
  |
5 | fn main() -> Int = at([1, 2, 3], 5)
  |                    ^^^^^^^^^^^^^^^^
   = expected: `requires 0 <= i && i < xs.len()`

        

      

      
Type-level mistakes are caught in the browser too. Press the button to ask the in-page compiler about a match that forgets a case:

      

        
type Light = Red | Yellow | Green

fn next(l: Light) -> Light = match l {
  Red => Green
  Green => Yellow
}

fn main() -> Light = next(Red)
